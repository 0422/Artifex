# M5 工具库

## 1. 需求背景

本次迭代需要在 Artifex 前端增加一个统一的工具库模块，将相对独立的学习辅助功能集中到一个入口中，避免左侧一级导航持续膨胀，并为后续接入更多小工具建立一致的页面与路由规范。

本阶段只考虑桌面 Web 端，不处理移动端底部导航、移动端卡片布局或触屏交互适配。

需求在实现过程中分为三个部分：

1. 在左侧导航增加“工具库”入口，右侧展示工具卡片；卡片包含工具名称和功能介绍，点击后进入对应工具页面，工具页面左上角提供返回图标。
2. 将原左侧导航中的“学习路径”和“内容捕获”迁移为工具库卡片，通过工具库进入，同时保留已有功能和旧地址兼容能力。
3. 将外部单文件应用 `E:\4Della\StowIt3D\集装箱装载计算器V4.html` 的完整功能作为“集装箱装载计算器”卡片接入工具库。

## 2. 需求分析

### 2.1 现有前端基础

项目当前使用 React 19、TypeScript、React Router 6、Tailwind CSS 4 和 Lucide 图标库。主页面通过 `Layout` 提供可调宽度的桌面左侧导航，通过 `<Outlet />` 渲染右侧内容，因此工具库适合直接作为现有认证布局下的新一级路由。

项目已经存在场景卡片、统一按钮样式和深色 `zinc + teal` 视觉体系，可以复用其交互与视觉语言，不需要引入新的 UI 库。

### 2.2 核心设计问题

工具库需要同时容纳两类功能：

- 轻量工具：完全由 React 组件实现，例如文本统计、英文大小写转换、逐行去重。
- 独立业务页面：已有完整页面或外部单页应用，例如学习路径、内容捕获、集装箱装载计算器。

如果所有工具都强制塞进同一个动态组件路由，会导致已有业务页面需要无意义的包装或重构。因此工具注册表同时保存工具卡片的统一元数据和目标地址，并允许轻量工具额外注册 React 组件。工具库首页只关注卡片信息和跳转地址，具体路由根据工具类型选择统一工具页、现有业务页或专用容器页。

### 2.3 路由原则

所有工具统一使用 `/tools` 命名空间：

| 地址 | 功能 |
| --- | --- |
| `/tools` | 工具库首页 |
| `/tools/learning-path` | 学习路径 |
| `/tools/content-capture` | 内容捕获 |
| `/tools/container-loading-calculator` | 集装箱装载计算器 |
| `/tools/text-statistics` | 文本统计 |
| `/tools/case-converter` | 英文大小写转换 |
| `/tools/line-deduplicator` | 逐行去重 |

这样做有三个好处：

- 用户进入任意工具页面时，左侧“工具库”导航能够保持激活状态。
- 工具地址语义清晰，支持直接收藏和分享。
- 后续新增工具不会继续占用一级路由或一级导航。

原有 `/path` 和 `/capture` 地址通过 React Router 自动重定向到新地址，避免旧书签或已有调用失效。

## 3. 总体方案

### 3.1 工具注册表

新增 `frontend/src/lib/tools.ts`，集中维护工具的以下信息：

- `id`：稳定的工具标识。
- `name`：卡片和详情页展示名称。
- `description`：工具功能介绍。
- `icon`：Lucide 图标组件。
- `path`：工具卡片跳转地址。
- `component`：可选的轻量 React 工具组件。

工具库首页和统一工具详情页共用该注册表，避免名称、说明、图标和路由散落在多个文件。后续增加轻量工具时，只需实现组件并补充一项注册数据。

### 3.2 工具库首页

新增 `frontend/src/pages/ToolLibraryPage.tsx`，提供桌面端工具卡片网格。每张卡片展示：

- 工具图标。
- 工具名称。
- 功能介绍。
- “打开工具”提示及箭头反馈。

卡片沿用项目的深色视觉体系，通过边框、背景、轻微位移和颜色变化提供悬停反馈。

### 3.3 统一轻量工具详情页

新增 `frontend/src/pages/ToolPage.tsx`，处理带有 `component` 的工具：

- 根据 URL 中的 `toolId` 查询工具注册表。
- 左上角提供明确返回 `/tools` 的图标，而不是使用 `navigate(-1)`，避免从外部链接进入后返回站外。
- 统一展示工具图标、名称和说明。
- 渲染对应工具组件。
- 无效或不支持动态渲染的工具 ID 自动返回工具库。

### 3.4 已有业务页面迁移

“学习路径”和“内容捕获”不重写业务逻辑，只调整入口和页面导航：

- 从 `Layout` 的一级导航配置中移除。
- 在工具注册表中增加对应卡片。
- 将页面路由迁移到 `/tools/learning-path` 和 `/tools/content-capture`。
- 在两个页面左上角增加返回工具库按钮。
- 将引导流程结束后的跳转从 `/path` 修改为 `/tools/learning-path`。
- 保留 `/path`、`/capture` 到新地址的兼容重定向。

该方案减少了一级导航数量，同时不会影响已有 API、状态管理和业务组件。

### 3.5 集装箱装载计算器集成

源文件是约 86 KB 的完整 HTML 单页应用，内部包含：

- 集装箱规格与自定义集装箱管理。
- 多 SKU 参数配置。
- 装载计算和按 SKU 重排。
- Three.js 三维装载结果及视角、图层控制。
- 体积、重量、件数等统计信息。
- PNG 截图和 CSV 清单导出。
- 浏览器 `localStorage` 配置存储。
- 可选的兼容 OpenAI `/chat/completions` 接口调用。

该页面具有大量独立 DOM、CSS 和模块脚本。直接转换成 React 组件会产生较大重写成本和回归风险，并可能让页面的全局 CSS 污染主应用。因此采用“项目内静态资源 + iframe 隔离”的方案：

1. 将源 HTML 完整复制为 `frontend/public/tools/container-loading-calculator.html`，发布后不依赖开发电脑上的 `E:\4Della` 路径。
2. 新增 `ContainerLoadingCalculatorPage.tsx` 作为 React 容器页，提供统一返回栏、标题、说明和加载状态。
3. 使用 iframe 加载静态 HTML，使其样式、DOM 和 JavaScript 与主应用隔离。
4. iframe 开放 `allow-scripts`、`allow-same-origin`、`allow-downloads` 和 `allow-forms`，以保留 Three.js、浏览器存储、截图/CSV 下载和表单功能。

计算器的 Three.js 模块目前仍通过 import map 从 `unpkg.com` 加载，因此首次打开三维工具时需要网络访问。AI 分析功能仅在用户自行填写兼容接口地址、API Key 和模型后才会发起网络请求，配置保存在计算器 iframe 对应源的 `localStorage` 中。

## 6. 实现细节与决策

### 6.1 导航激活

工具库使用 React Router 的 `NavLink`。目标地址为 `/tools` 时，默认非 `end` 匹配会覆盖 `/tools/*`，因此打开任意工具页面时左侧工具库入口保持高亮。

### 6.2 返回行为

所有工具详情页的返回图标都明确指向 `/tools`。没有使用浏览器历史后退，因为用户可能直接通过地址或外部链接进入工具页面，历史后退无法保证回到工具库。

### 6.3 轻量工具与独立页面分流

工具注册表中的 `component` 是可选字段：

- 存在 `component`：由通用 `ToolPage` 渲染。
- 不存在 `component`：卡片跳转到显式注册的独立路由。

这使卡片表现保持一致，同时避免强迫复杂业务页面使用相同的内容容器。

### 6.4 计算器隔离与权限

集装箱计算器通过 iframe 隔离，避免其中的全局标签样式、CSS 变量、全屏布局和事件绑定影响 React 主应用。

iframe sandbox 权限用途如下：

| 权限 | 用途 |
| --- | --- |
| `allow-scripts` | 执行计算逻辑、Three.js 和交互脚本 |
| `allow-same-origin` | 使用浏览器存储并正常加载同源静态资源 |
| `allow-downloads` | 导出 PNG 截图和 CSV 清单 |
| `allow-forms` | 保留页面表单交互能力 |

由于 `allow-scripts` 与 `allow-same-origin` 同时开启时隔离强度有限，当前方案的信任前提是该 HTML 已作为项目代码审查并纳入版本管理，而不是加载任意用户提供的远程页面。

## 8. 后续扩展方式

### 8.1 新增轻量 React 工具

1. 在 `frontend/src/components/tools/` 下新增工具组件。
2. 在 `frontend/src/lib/tools.ts` 中导入组件和图标。
3. 向 `TOOLS` 注册 `id`、`name`、`description`、`icon`、`path` 和 `component`。
4. 通用 `/tools/:toolId` 路由会自动渲染该工具，无需再修改 `App.tsx`。

### 8.2 新增复杂业务工具

1. 新增独立页面组件。
2. 在工具注册表中添加卡片信息和明确的 `path`，不设置 `component`。
3. 在 `App.tsx` 中把独立路由放在 `/tools/:toolId` 之前，防止被动态工具路由提前匹配。
4. 页面左上角提供返回 `/tools` 的入口。

### 8.3 新增外部单页工具

如果外部页面具有完整、独立且已验证的 HTML/CSS/JavaScript，可沿用集装箱计算器方案：

1. 将资源纳入 `frontend/public/tools/`，不要依赖开发机绝对路径。
2. 检查外链脚本、网络请求、浏览器存储、下载和跨域需求。
3. 根据最小权限原则设置 iframe sandbox。
4. 使用 React 容器页提供项目统一导航和加载反馈。
5. 对静态副本执行完整性检查，并验证构建产物确实包含该文件。

## 9. 当前边界

- 本阶段只优化桌面 Web 端，未调整移动端底部导航和移动布局。
- 工具卡片暂未增加搜索、分类、排序和权限字段；当前数量较少，统一平铺更直接。
- 集装箱计算器 Three.js 依赖仍从 CDN 加载，离线环境下三维部分无法启动。如后续要求完全离线，应将 Three.js 与 OrbitControls 改为项目内静态依赖或重构为 React/Three.js 模块。
- 集装箱计算器中的 AI API Key 由页面保存到浏览器 `localStorage`。若用于生产环境，建议后续改为由 Artifex 后端代理 AI 请求，避免浏览器长期保存第三方密钥。

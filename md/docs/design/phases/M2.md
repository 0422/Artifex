## 1. 阶段目标与范围

M2 将 M1 的通用学习框架收敛到一个可验证的核心价值：**外语场景 AI 对话学习**。

本阶段跑通了完整路径：

```text
注册/登录
  → 自动获得种子场景
  → 选择或管理场景卡片
  → 与 AI 进行文本对话
  → 获得渐进式纠错
  → 主动结束会话
  → 自动生成学情报告
  → 在仪表盘复盘与查看聚合统计
```

M2 明确不包含以下能力：

- STT/TTS 语音输入与播放；界面保留 V1.1 入口。
- FSRS 记忆系统与复习页。
- 学习路径自适应调整。
- 费曼检验、兴趣检验、DLE/MHI 等增强指标。
- VRM 3D 数字人。

### 2.2 WebSocket 场景对话

实现地址：

```text
ws://127.0.0.1:8000/api/v1/chat/ws
```

客户端发送协议：

```json
{"type":"authenticate","token":"ACCESS_TOKEN"}
{"type":"start_session","scenario_id":"UUID","difficulty":"N3"}
{"type":"text_message","content":"..."}
{"type":"end_session"}
```

服务端事件：

```text
authenticated
session_started
ai_response
correction
session_ended
report_generating
session_report
error
```

实现内容：

- 连接建立后，JWT 在第一帧发送，避免令牌出现在 URL、代理日志和浏览历史中。
- 启动会话时校验场景归属与可用状态。
- AI 根据场景、语言和难度生成角色提示词与开场白。
- 用户消息先落库，再调用 LLM，减少模型调用异常造成的消息丢失。
- LLM 一次返回结构化 `reply + correction`。
- 纠错分为 `minor` 和 `major`，包含原句、修正句和解释。
- LLM 不可用时返回降级响应，并通过 `degraded=true` 标识。
- 用户断开连接时自动完成活动会话，避免长期残留 active 状态。
- 数据库是会话状态的事实来源，没有引入 Redis 或全局内存 session dict。
- 修正 `ended_at` 为 PostgreSQL 时区感知时间类型。

相关文件：

### 2.3 学情报告

结束会话后自动生成报告，报告包含：

- 对话表现摘要 `summary`
- 0-5 个薄弱点 `weak_points`
- 每个薄弱点的分类、稳定标签、描述、示例和建议
- 后续练习建议 `suggestions`
- 表现分 `performance_score`（0-100）
- `no_prominent_issues`
- `degraded`
- `insufficient_data`

实现特性：

- 报告存入 `ChatSession` 的 JSONB 字段。
- 报告生成与 `conversation_practice` 类型的 `LearningEvent` 在同一事务中提交。
- 同一会话重复请求报告时保持幂等，不重复写事件。
- 数据不足时生成明确的降级报告，不伪造三个薄弱点。
- 标签使用稳定 ASCII 格式，例如：

```text
vocab:restaurant-counters
grammar:article-use
expression:target-language-use
pragmatics:politeness
```

相关文件：

```text
backend/app/schemas/report.py
backend/app/services/report_service.py
```

### 2.10 黑屏问题修复

真实浏览器测试中发现：点击“开始练习”后页面黑屏。

控制台错误：

```text
NotFoundError: Failed to execute 'insertBefore' on 'Node'
An error occurred in the <CircleStop> component
```

根因：

- 会话状态变化时，React 将“开始练习”的 `Sparkles` SVG 替换为“结束会话”的 `CircleStop` SVG。
- 浏览器翻译功能或扩展修改了 React 管理的 DOM 节点。
- React 19 提交新节点时，原参照节点已不再属于预期父节点，导致整棵组件树退出。

修复：

- “开始练习”和“结束会话”按钮始终保留在 DOM 中，仅切换 `display`。
- 增加应用级 `AppErrorBoundary`，出现渲染异常时展示可恢复页面，而不是整页黑屏。

相关文件：

```text
frontend/src/pages/ChatPage.tsx
frontend/src/components/AppErrorBoundary.tsx
frontend/src/main.tsx
```

## 3. 与原计划不同的实现决策

| 项目 | 原计划/文档表述 | 最终实现 | 原因 |
|---|---|---|---|
| WS 鉴权 | URL query token | 连接后第一帧发送 token | 避免令牌泄露到 URL 和日志 |
| 会话状态 | 内存 dict + DB | 只以 DB 为事实来源 | 多进程一致性更好，减少重复状态 |
| 模型输出 | 尝试流式 | 结构化整段 JSON + 前端打字机 | 纠错与回复必须保持同一次结构化响应 |
| Redis | 可选 | 未引入 | MVP 会话不需要额外状态层 |
| 自动结束 | 3 分钟自动提示 | 前端 3 分钟提示，仍由用户主动结束 | 避免强制中断对话 |
| 数字人 | 2D 正式立绘 | 图标 + CSS 交互占位 | 当前环境未生成正式位图，先验证布局与状态系统 |
| 学情来源 | ChatSession + LearningEvent | Dashboard 以 ChatSession 为主 | 避免两个数据源统计不一致 |

## 7. 已知限制与待深化点

### 7.1 正式 2D 数字人素材

现状：使用 Lucide 图标和 CSS 状态光晕，只完成交互骨架。

下一步：

- 设计统一角色设定、色彩和服装。
- 生成同一角色的 neutral/happy/thinking/relaxed/sad 五套一致立绘。
- 使用 WebP/AVIF 并控制资源大小。
- 提供低分辨率占位，避免首次加载闪烁。
- 根据对话语义和纠错严重度切换表情，而不只是根据请求状态切换。

### 7.2 纠错与前端消息关联

现状：后端 `correction.message_id` 是数据库中的用户消息 ID；前端发送消息时没有获得该 ID，因此前端把纠错关联到“最近一条尚未纠错的用户消息”。在服务端严格顺序发送时可用，但协议不够显式。

建议：

- 客户端发送 `client_message_id`。
- 后端在 `user_message_accepted` 或 `correction` 中同时返回 client/server ID。
- 前端按 ID 精确关联，支持未来并发、重试和消息恢复。

### 7.3 WebSocket 重连与恢复

现状：连接断开后会话在后端完成，前端不会自动重连或恢复历史消息。

建议：

- 增加指数退避重连。
- 区分临时断网和主动退出。
- 提供 `resume_session` 或 REST 会话消息读取接口。
- 记录 WebSocket 心跳和连接质量。

### 7.4 Token 刷新与 WebSocket

现状：HTTP 使用 refresh cookie 自动更新 access token；已建立的 WebSocket 不会在 token 刷新后重新鉴权。

建议：

- 在 token 即将过期前更新并重连。
- 或使用短期 WebSocket ticket，由 HTTP 鉴权接口签发。

### 7.5 真正的流式体验

现状：模型返回完整结构化 JSON 后，前端模拟打字机效果；用户看到的是渐进展示，不是真正 token streaming。

建议：

- 将回复文本与纠错判定拆成两段事件。
- 回复使用流式 token/delta，纠错在回复后异步返回。
- 评估额外调用成本、延迟和内容一致性。

### 7.6 对话结束策略

现状：前端在 3 分钟时提示结束，但后端没有统一的 3 分钟提示事件，也没有最大会话时长限制。

建议：

- 后端记录时长并发出 `session_end_available`。
- 增加最大空闲时间与最大会话时长。
- 页面刷新、断网、浏览器休眠后确保时长计算准确。

### 7.7 学情质量评估

现状：已有 schema 约束、降级和稳定标签，但尚无针对纠错准确率与报告有用性的人工评测集。

建议：

- 建立 30-50 段英语/日语标注对话。
- 评估明显错误召回率、轻微错误误判率、解释可理解度。
- 校准 `performance_score`，减少不同场景之间评分漂移。
- 合并语义相同但标签不同的薄弱点。
- 记录 prompt/model 版本，便于回归对比。

### 7.8 仪表盘深化

现状：提供最小的次数、时长、平均分、场景分布、薄弱点和历史详情。

建议：

- 增加 7/30 天趋势。
- 增加语言和难度筛选。
- 展示分数与薄弱点随时间变化。
- 从薄弱点直接创建下一次练习场景。
- 数据量增大后为报告标签建立规范化索引或独立分析表。

### 7.9 场景库深化

建议：

- 场景搜索、分类、排序和收藏。
- 已停用场景恢复功能。
- LLM 辅助生成场景，但保留用户确认。
- 社区模板或官方场景包。
- 场景 prompt 版本化和质量评估。

### 7.10 前端稳定性与测试

现状：已通过真实浏览器 smoke test，但项目尚未引入可持续运行的前端 E2E 测试框架。

建议：

- 引入 Playwright，固化登录、开始对话、结束、仪表盘等关键路径。
- Mock LLM，避免常规 CI 消耗真实模型额度。
- 保留少量真实模型 nightly/手动验收。
- 增加 React 组件测试和 WebSocket 状态机测试。
- 明确浏览器自动翻译兼容策略，可在应用根节点设置不翻译标记。

### 7.11 安全与生产准备

在公开部署前需要：

- 更换所有开发环境密钥和默认 JWT secret。
- 确保 `.env` 不进入 Git。

- 增加结构化日志、错误追踪和模型调用指标。

## 9. M2 阶段结论

M2 已完成“**能选择场景、能与 AI 对话、能得到纠错、能生成学情、能在仪表盘复盘**”的最小产品闭环。

当前版本已不只是接口拼装：场景 CRUD、WebSocket 协议、模型结构化输出、会话落库、报告事务、统计聚合、桌面/移动前端和真实浏览器链路都经过验证。下一阶段的重点不应继续横向增加大量模块，而应围绕以下三个方向深化：

1. **对话质量**：纠错准确、回复自然、评分可信。
2. **对话可靠性**：断线重连、消息精确关联、自动化回归。
3. **角色与语音体验**：正式 2D 形象、语音链路和更自然的状态反馈。

完成这些深化后，再将对话产生的薄弱点接入记忆系统与自适应学习路径，产品的长期学习价值会更加明确。

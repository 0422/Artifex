# 第一部分：需求分析

## 1. 产品背景

当前项目已经具备情境对话、场景卡 CRUD、语音输入输出、数字人、学习报告、内容捕获和学习路径等基础能力，但场景卡目前只以一个扁平列表存在于对话页面，主要服务于英语和日语角色扮演。

随着场景内容扩展到语言、历史、政治、艺术、电影等领域，现有列表将出现以下问题：

- 场景数量增加后难以定位和管理。
- 语言、朝代、制度、流派等分类维度互不相同，无法只靠 `language + difficulty` 表达。
- 历史、政治和艺术类学习不一定属于角色扮演，需要主题讨论、辩论、资料分析等对话模式。
- 内容捕获、学习路径、情境对话和学习报告之间缺少统一的内容入口。
- 用户创建场景时缺少学习目标、AI 角色、讨论提纲和评价标准等配置。

因此需要在左侧全局导航中增加“知识库”入口，将其建设为可分类、可检索、可编辑、可进入 AI 对话并能沉淀学习结果的场景内容中心。

## 2. 产品定位

知识库不是普通文件夹，也不是只读百科。它应当是 Artifex 中“组织学习内容并发起学习行为”的核心栏目。

知识库承担四项职责：

1. 分类负责帮助用户定位内容。
2. 标签负责跨分类组织内容。
3. 学习场景卡负责定义一次学习或讨论活动。
4. 对话和学习报告负责形成练习反馈与后续推荐。

产品目标是让用户能够在 30 秒内找到适合自己的学习场景，并在不超过两次主要点击后进入 AI 对话。

## 3. 目标用户与核心需求

### 3.1 学习者

学习者关注的是快速找到内容、理解学习目标、开始练习和查看进步，不应被复杂的内容管理流程打断。

核心需求：

- 按领域、分类、难度和学习方式查找场景。
- 收藏常用场景，查看最近学习和需要复习的场景。
- 在开始前了解场景目标、预计时长、AI 身份和讨论方式。
- 使用默认配置快速开始，也能在需要时调整难度、语言和对话模式。
- 对话结束后把练习次数、薄弱点和掌握程度回写到场景卡。

### 3.2 内容创建者

内容创建者可能也是普通学习者，需要创建私人场景，也可能负责维护系统内置知识内容。

核心需求：

- 创建领域、分类、标签和学习场景卡。
- 编辑学习目标、对话背景、角色、提纲、评价标准和资料来源。
- 复制系统场景后进行个性化修改。
- 移动分类、批量加标签、归档和恢复内容。
- 在发布前预览场景实际生成的 AI 对话效果。

### 3.3 内容维护者

后续若引入系统公共内容或多人共享，需要支持内容质量、来源和版本治理。

核心需求：

- 区分系统内容、用户内容和共享内容。
- 审查史实、引用、版权和争议观点。
- 管理版本、发布状态和适用范围。
- 查看场景使用频率、完成率和用户反馈。

## 4. 信息架构

### 4.1 不采用写死的三级数据库结构

界面可以展示三级目录，但数据库不应写死为一级、二级、三级字段。

例如：

| 领域 | 主分类 | 主题维度 | 场景卡示例 |
| --- | --- | --- | --- |
| 语言 | 英语、日语、韩语 | 听、说、读、写 | 英语面试、日语餐厅点餐 |
| 历史 | 唐、宋、明、清 | 军事、政策、民生、经济 | 讨论王安石变法 |
| 政治 | 民主制、君主制、联邦制 | 自由主义、保守主义等 | 比较总统制与议会制 |
| 艺术 | 绘画、雕塑、建筑 | 流派、技法、时期 | 分析印象派用色 |
| 电影 | 类型、国家、导演 | 叙事、镜头、表演 | 讨论长镜头的作用 |

其中“宋代”和“政策”属于两个不同维度。若严格写成三级树，“王安石变法”可能需要在多个目录中重复创建。

推荐采用：

```text
领域 Domain
分类节点 CategoryNode，可建立任意层级和排序
主题标签 Tag，可跨分类复用
学习场景卡 ScenarioCard，可关联多个分类和标签
```

界面仍可向用户呈现熟悉的树形目录，例如“历史 > 宋代”，同时允许通过“政策、财政、民生”标签交叉筛选。

### 4.2 推荐领域

首期内置领域建议包括：

- 语言
- 历史
- 政治
- 艺术
- 电影
- 个人技能
- 自定义领域

领域不应写成后端枚举，以免未来增加哲学、法律、文学、经济等领域时必须修改数据库枚举和前后端类型。

### 4.3 系统视图

除领域分类树外，知识库应提供以下固定入口：

- 全部场景
- 最近学习
- 收藏
- 需要复习
- 我创建的
- 草稿
- 已归档

这些入口属于查询视图，不应作为普通分类节点写入分类树。

## 5. 学习场景卡

“情景卡”对于语言角色扮演很自然，但历史、政治和艺术不一定存在具体生活情境，因此界面统一使用“学习场景卡”，数据库可以继续沿用 `ScenarioCard`。

### 5.1 基本信息

每张卡建议包含：

- 标题和简短摘要。
- 所属领域、主分类和主题标签。
- 场景类型、难度和预计时长。
- 对话输出语言。
- 学习目标和建议前置知识。
- AI 身份、用户身份和讨论背景。
- 开场问题、讨论提纲和关键知识点。
- 评价维度和完成条件。
- 参考资料、出处和观点说明。
- 草稿、可用、归档状态。
- 收藏状态、练习次数、最近练习时间和掌握程度。

### 5.2 场景类型

首期建议支持：

| 类型 | 典型用途 |
| --- | --- |
| 角色扮演 | 语言口语、面试、商务谈判、生活情境 |
| 主题讨论 | 历史事件、电影主题、艺术作品讨论 |
| 苏格拉底问答 | 通过连续追问帮助用户建立概念和推理 |
| 观点辩论 | 政治制度、伦理问题和争议性议题 |
| 资料分析 | 史料、文章、政策文本和图表解读 |
| 作品赏析 | 绘画、电影、文学和建筑分析 |

场景类型将决定对话引擎使用的 Prompt 模板、AI 行为和报告评价方式。

### 5.3 卡片状态与权限

建议支持：

- `draft`：草稿，不出现在正常浏览列表。
- `published`：可学习和对话。
- `archived`：停止使用，但保留历史会话关联。
- `system`：系统内置，只读，用户可以复制后修改。
- `private`：用户私人内容。
- `shared`：后续用于团队或公开共享。

删除场景默认采用归档或停用，不直接物理删除，保证历史会话和学习报告仍可追溯。

## 6. 核心用户流程

### 6.1 查找并开始学习

```text
进入知识库
    ↓
选择领域、分类或使用搜索
    ↓
浏览学习场景卡
    ↓
单击卡片打开右侧预览
    ↓
开始对话 / 调整后开始
    ↓
携带 scenario_id 进入对话页
    ↓
完成对话并生成学习报告
    ↓
回写练习次数、薄弱点和掌握状态
```

单击卡片不应直接开始对话，否则容易误触。预览区提供三个明确操作：

- `开始对话`：直接使用卡片默认配置。
- `调整后开始`：临时调整难度、输出语言、AI 角色或讨论模式。
- `编辑`：进入完整编辑器。

### 6.2 创建场景

```text
新建场景卡
    ↓
选择领域和场景类型
    ↓
填写基本信息与学习目标
    ↓
配置角色、讨论提纲和评价标准
    ↓
预览 AI 对话
    ↓
保存草稿或发布
```

编辑器应支持自动保存草稿。若存在未保存修改，关闭或跳转前需要提示。

### 6.3 对话结束后的回流

学习报告除了进入仪表盘，还应回写到知识库：

- 场景卡练习次数加一。
- 更新最近学习时间。
- 更新掌握度或复习状态。
- 展示本场景常见薄弱点。
- 推荐同分类下的下一张卡。

## 7. 页面布局与交互

### 7.1 全局导航

在左侧导航栏增加“知识库”入口，建议放在“情境对话”之后、“学习仪表盘”之前，使用 Lucide 的 `Library` 或 `BookOpen` 图标。

建议导航顺序：

```text
情境对话
知识库
学习仪表盘
内容捕获
学习路径
```

### 7.2 桌面端布局

采用适合内容管理和反复学习的三栏工作区：

```text
┌──────────────┬────────────────────────────┬──────────────────┐
│ 分类导航      │ 搜索、筛选、场景卡列表       │ 场景卡预览        │
│              │                            │                  │
│ 全部知识      │ [搜索框] [筛选] [排序]       │ 标题、摘要         │
│ 最近学习      │                            │ 学习目标           │
│ 收藏          │ 场景卡  场景卡  场景卡       │ 讨论提纲           │
│              │ 场景卡  场景卡  场景卡       │ 最近练习结果       │
│ 语言          │                            │                  │
│  └ 英语       │                            │ [编辑] [开始对话]  │
│ 历史          │                            │                  │
└──────────────┴────────────────────────────┴──────────────────┘
```

布局规则：

- 分类栏建议宽度 `240～300px`。
- 右侧预览栏建议宽度 `340～420px`。
- 中间区域自适应剩余空间。
- 分类栏和预览栏可以复用当前项目已有的拖拽分割线模式。
- 中间区域支持卡片视图和紧凑列表视图切换。
- 不使用大面积营销式 Hero，也不把整个页面包在卡片中。

### 7.3 卡片列表

场景卡作为重复内容单元，可以使用紧凑卡片。卡片上直接展示：

- 领域图标或色条。
- 标题和两行摘要。
- 场景类型、难度和预计时长。
- 主要标签。
- 最近学习或掌握状态。
- 收藏按钮和更多菜单。

卡片主要交互：

- 单击：选中并打开右侧预览。
- 收藏图标：直接收藏，不打开详情。
- 更多菜单：编辑、复制、移动分类、归档。
- 不依赖双击或仅在悬停时才能发现的关键操作。

### 7.4 右侧预览

预览栏用于降低进入详情页的频率，应展示：

- 标题、摘要和分类路径。
- 学习目标、预计时长和难度。
- AI 角色、用户角色和开场问题。
- 讨论提纲和参考资料摘要。
- 最近一次练习结果。
- `编辑`、`调整后开始`、`开始对话`。

预览栏可以收起。没有选中卡片时显示最近学习或推荐内容，而不是空白说明页。

### 7.5 移动端布局

移动端不同时展示三栏，采用逐级钻取：

```text
领域与固定视图
    ↓
分类页
    ↓
场景卡列表
    ↓
场景卡详情
```

移动端详情页底部固定“开始对话”主按钮，编辑、收藏和归档放入顶部菜单。筛选条件使用底部抽屉，不使用占据大部分屏幕的永久侧栏。

## 8. 搜索、筛选与排序

知识库内容增多后，搜索的重要性会高于分类树。首期至少支持：

- 搜索标题、摘要和标签。
- 按领域、分类、场景类型和难度筛选。
- 筛选收藏、最近学习、未练习和需要复习。
- 按最近更新、最近练习、名称和使用频率排序。
- 搜索结果显示分类路径，例如“历史 / 宋代 / 王安石变法”。
- 页面刷新和前进后退时保留搜索、筛选和选中卡片状态。

后续可以加入自然语言搜索，例如：“找一个适合 B1、练习商务英语谈判的场景”。

## 9. 场景编辑器

现有 `ScenarioManager` 只有名称、说明、语言和难度，适合快速创建语言场景，不足以承担知识库完整编辑任务。

建议编辑器分为四个标签页：

| 标签页 | 内容 |
| --- | --- |
| 基本信息 | 标题、摘要、领域、分类、标签、封面和状态 |
| 对话设计 | 场景类型、AI 角色、用户角色、开场方式和讨论提纲 |
| 学习设计 | 学习目标、难度、预计时长、评价维度和完成条件 |
| 资料与发布 | 参考资料、来源、版权、观点说明和可见范围 |

编辑器操作：

- 保存草稿。
- 预览对话。
- 保存并开始。
- 复制场景。
- 归档与恢复。
- 检测未保存修改。

对于复杂场景，Prompt 不直接暴露给普通用户编辑，而是通过结构化字段生成；高级模式后续再允许维护者编辑 Prompt 模板。

## 10. 各领域的特殊要求

### 10.1 语言

- 区分目标语言和界面语言。
- 支持听、说、读、写标签。
- 保留 CEFR、JLPT 等不同难度体系。
- 报告关注语法、词汇、流利度和表达自然度。

### 10.2 历史

- 保存时间范围、地区、朝代和资料来源。
- 区分史实、主流解释和争议观点。
- 报告关注时间线、因果关系、证据使用和概念准确性。

### 10.3 政治

- 保存制度适用国家、地区和历史时期。
- 标记理论流派和观点来源。
- AI 应区分事实描述、规范性判断和用户观点。
- 报告关注概念区分、论证结构、证据和反方回应。

### 10.4 艺术与电影

- 支持作品、作者、时期、流派和媒介元数据。
- 参考资料可以包含合法的图片链接或公开页面，但不能未经许可保存完整电影、剧本或受版权保护的大段内容。
- 报告关注观察细节、形式分析、语境和观点表达。

## 11. 与当前项目的衔接

### 11.1 现有场景卡

当前 `ScenarioCard` 只包含：

- `title`
- `description`
- `language`
- `difficulty`
- `is_active`

它目前属于单个用户，并通过 `ChatSession.scenario_id` 关联历史会话。该关联和会话中的场景标题快照可以继续保留。

需要扩展的关键字段包括领域、分类、标签、场景类型、学习目标、Prompt 配置、评价配置、预计时长、发布状态和可见范围。

### 11.2 对话引擎

当前 `scenario_engine.py` 明确要求 AI 扮演外语对话伙伴，只支持英语和日语难度指导。历史、政治和艺术场景不能直接复用这套 Prompt。

需要按 `scenario_mode` 选择模板，例如：

```text
role_play
guided_discussion
socratic_dialogue
debate
source_analysis
work_analysis
```

对话语言应成为独立字段，不能继续同时承担“场景所属领域”的作用。

### 11.3 对话页面

从知识库开始对话时建议跳转到：

```text
/chat?scenario=<scenario_id>
```

## 14. 非功能需求

### 14.1 性能

### 14.4 可访问性

- 分类树、筛选菜单和卡片操作支持键盘导航。

## 18. 关键产品原则

1. 分类用于定位，标签用于交叉组织，不能让分类树承担所有维度。
2. 场景卡必须对应一次明确的学习行为，而不只是知识介绍。
3. 默认路径要快，高级配置要可发现但不能阻塞普通学习者。
4. 对话、报告、知识库和学习路径必须通过同一个场景 ID 形成闭环。
5. 历史、政治等领域必须记录来源、时间和观点边界。
6. 系统内容与用户内容必须有明确的权限和复制规则。
7. 第一阶段优先完成查找、预览、开始对话和结果回写，不提前投入复杂共享和图谱能力。

# 第二部分：第一阶段实施总结

> 实施日期：2026-08-16  
> 实施范围：知识库第一阶段 MVP 的核心浏览、管理和对话接入链路。  
> 当前结论：核心链路已经可用，但第一阶段需求尚未全部完成；具体差异以文首实施进度表为准。

## 1. 本次实现概览

本次实现将原先仅存在于对话页中的扁平场景列表，扩展成独立的知识库模块。用户现在可以从全局导航进入知识库，按领域和任意层级分类浏览场景卡，创建或编辑学习场景，在右侧预览完整信息，并携带场景 ID 跳转到对话页直接开始相应主题的练习或讨论。

实现时保留了原有场景卡和 WebSocket 对话协议，没有另起一套彼此割裂的内容与对话模型。知识库负责组织和发现内容，现有对话模块继续负责执行场景，从而降低改造范围并保证原有语言练习仍可使用。

## 2. 前端功能与实现方式

### 2.1 导航和页面路由

- 在全局左侧导航中增加“知识库”入口。
- 新增 `/knowledge` 路由和独立的 `KnowledgePage` 页面。
- 保持项目现有深色、紧凑视觉风格，不改变原有认证和整体布局结构。

### 2.2 响应式知识库布局

桌面端采用三栏结构：

1. 左栏展示分类树和各节点包含的场景数量。
2. 中栏展示搜索框、新建入口和场景卡网格。
3. 右栏展示当前卡片详情、标签、分类、难度、预计时长以及操作按钮。

移动端不强行保留三栏，而是使用分类下拉选择、卡片列表和覆盖式全屏预览，保证窄屏下仍能完成分类选择、查看卡片和开始对话。

### 2.3 分类浏览与创建

- 分类树支持展开和收起，并可递归渲染任意层级，不把数据库限制为固定三级。
- 点击父分类时，后端会查询其自身及所有后代分类关联的场景，因此领域根节点可以聚合展示整个领域的内容。
- 已提供新建分类弹窗，可设置名称、领域和父分类，既能创建根分类，也能创建子分类。
- 分类节点显示聚合后的卡片数量，父节点数量包含后代节点中的场景。
- 后端已具备分类更新和软归档接口，但本阶段前端暂未提供重命名、移动、排序、归档和恢复操作入口。

### 2.4 场景卡浏览、搜索与编辑

- 支持展示场景名称、说明、领域、对话模式、语言、难度和预计时长。
- 支持按分类筛选；搜索输入使用约 250ms 防抖，当前匹配标题和说明。
- 支持创建和编辑场景，可配置领域、分类、场景模式、预计时长、输出语言、难度和标签。
- 点击场景卡只打开预览，不会直接开始对话，避免误触；用户在预览中确认后再点击“开始对话”。
- 后端数据模型和接口支持一个场景关联多个分类，但当前编辑器使用单选分类控件，前端多分类编辑仍需补齐。
- 标签现已保存并展示，但搜索尚未匹配标签，也没有标签筛选器。

### 2.5 对话模块联动

- “开始对话”跳转到 `/chat?scenario=<场景ID>`。
- 对话页读取 `scenario` 查询参数，并由场景管理组件自动选中目标场景。
- 复用原有会话启动和 WebSocket JSON 合同，没有为知识库新增一条不兼容的对话链路。
- 这一实现使知识库成为内容入口，同时让场景 ID 继续作为知识库、对话会话和后续学习报告之间的关联键。

## 3. 后端功能与实现方式

### 3.1 分类数据模型

新增 `knowledge_categories` 表，核心字段包括：

- `user_id`：按用户隔离私人知识库数据。
- `parent_id`：分类自关联，支持任意层级树。
- `name`、`description`、`domain`：表达分类内容和所属领域。
- `sort_order`：为后续手动排序预留。
- `is_active`：支持软归档，避免直接删除历史组织数据。

分类读取时先取得当前用户的有效节点，再在服务层构造树结构并递归汇总场景数量。创建和更新分类时会校验父节点属于当前用户，并阻止分类直接成为自己的父分类。

### 3.2 场景卡扩展

在原有 `scenario_cards` 上增加：

- `domain`：语言、历史、政治、艺术、电影或自定义领域。
- `scenario_mode`：定义 AI 应采取的对话方式。
- `estimated_minutes`：供用户判断学习成本。
- `tags`：以 JSONB 保存主题标签。

新增 `scenario_category_links` 中间表，使场景卡与分类形成多对多关系。同一场景因此可以出现在多个分类下而无需复制，这也为以后按“朝代”“政策”“人物”等不同维度组织同一历史场景留出了空间。

### 3.3 API 能力

新增的分类 API 包括：

- `GET /knowledge/categories/tree`：读取当前用户的分类树。
- `POST /knowledge/categories`：创建根分类或子分类。
- `PUT /knowledge/categories/{id}`：更新名称、父分类、顺序或状态等字段。
- `DELETE /knowledge/categories/{id}`：软归档分类。

原有场景 API 在 CRUD 基础上扩展了 `domain`、`category_id` 和 `q` 查询参数，并返回标签与分类摘要。分类筛选会递归包含后代分类；所有查询和写入继续按当前登录用户隔离。

### 3.4 默认数据和旧数据兼容

Alembic 迁移为每个已有用户创建语言、历史、政治、艺术和电影等默认领域分类及其基础子分类。已有场景卡保持不变，并自动关联到“语言 / 日语”，从而避免升级后旧场景突然变成不可见或未分类数据。

## 4. 对话能力深化

### 4.1 新增语言、难度和模式

- 场景语言增加中文 `zh`，用于历史、政治、艺术、电影等中文专题讨论。
- 通用难度增加 `beginner`、`intermediate`、`advanced`，与语言学习使用的 CEFR/JLPT 等级并存。
- 场景模式增加角色扮演、主题讨论、苏格拉底问答、观点辩论、资料分析和作品赏析。

### 4.2 Prompt 分流

Prompt 生成器根据 `scenario_mode` 区分两类主流程：

- `role_play` 继续使用原有语言角色扮演逻辑，保持纠错反馈结构。
- 非角色扮演模式使用通用专题讨论逻辑，根据具体模式引导探索、追问、论证、证据分析或作品分析。

专题讨论要求 AI 使用场景指定语言、匹配难度、每轮控制重点，并在历史或政治主题中承认合理的不确定性和不同解释。用户填写的场景内容仍被标记为不可信上下文，避免其中的文本越权改变系统规则。

为兼容现有前端和 WebSocket 消息结构，非语言讨论仍返回 `reply`，并将 `correction` 设为 `null`。这样可先实现多领域对话，而不必在第一阶段同步重写整个报告展示协议。

## 5. 关键技术考量

### 5.1 任意层级树而非固定三级

UI 可以按产品规划呈现三级，但数据层使用 `parent_id` 自关联。这样既能表示“语言 / 日语 / 听力”，也能按需要继续增加更深层级，并避免以后修改表结构。

### 5.2 分类与标签分工

分类承担稳定的主浏览路径，标签承担可交叉的主题维度；场景与分类采用多对多关系。该设计避免把历史时期、政策类型、人物、流派等所有维度都硬塞进一棵树中。

### 5.3 复用现有场景和对话链

知识库没有新建另一套“知识条目”来复制场景卡，而是直接扩展 `ScenarioCard`。这样现有场景 CRUD、会话表、对话启动逻辑和历史记录仍围绕同一场景 ID 工作，减少数据割裂和迁移风险。

### 5.4 渐进兼容非语言领域

第一阶段先通过中文 locale、通用难度和讨论 Prompt 让非语言场景可对话，但不伪装成已经完成领域化学习评价。现有报告仍偏向词汇、语法、表达和语用，后续需要为史实、论证、证据、观点比较和作品分析建立独立指标。

9. 系统卡片、私人卡片、复制能力及对应权限规则。
10. 草稿、发布、归档状态和完整场景编辑器。

因此当前适合定义为“第一阶段核心链路完成”，而不是“整个第一阶段全部开发完毕”。下一轮建议优先补齐分类管理、组合筛选、多分类编辑和学习结果回写，这四项对知识库的日常可用性和学习闭环提升最大。

## 8. 后续深化方向

### 8.1 完整学习闭环

- 对话结束后按场景 ID 更新练习次数、最近练习、掌握度和复习时间。
- 在知识库提供收藏、最近学习、未练习、待复习等快捷视图。
- 将报告摘要展示在场景预览中，并提供继续练习或切换难度入口。

### 8.2 领域化 Prompt 和评价

- 历史：史实准确性、因果链、时序、史料证据和多种解释。
- 政治：概念边界、制度比较、论证质量、价值前提和反例。
- 艺术与电影：形式分析、语境、技法、视听语言和作品证据。
- 逐步替换当前偏语言学习的统一报告结构，并让 `LearningEvent` 记录真实领域。

### 8.3 与其他模块贯通

- 内容捕获结果可直接生成草稿场景卡并由用户确认分类和标签。
- 学习路径节点引用知识库场景卡，避免维护重复内容。
- 仪表盘增加领域、分类、模式和场景维度的统计。
- 基于报告薄弱点和复习状态推荐下一张场景卡。

### 8.4 内容治理与智能化

- 增加系统内容、私人内容和共享内容的权限边界与复制机制。
- 增加来源、引用、版本、争议观点和版权信息。
- 支持 AI 辅助分类、打标签、生成场景和自然语言检索，但自动生成内容先进入草稿并由用户确认。
